# VetHub

Two apps, no root package. `server/` is the Spring Boot API (Gradle, Java 25). `client/` is the SvelteKit UI (Bun). `scripts/` is shared shell tooling. Toolchain versions are pinned in `mise.toml` (Temurin 25, Bun 1.3.0, Node 22).

## Commands

Run Gradle from `server/` (wrapper is not at the repo root):

- Dev API: `./gradlew bootRun` — port `8080`, servlet context `/api`. `mise` sets `SPRING_PROFILES_ACTIVE=dev`.
- One test: `./gradlew test --tests 'dev.ilionx.workshop.api.owner.controller.OwnerControllerTest'`
- Full server gate: `./gradlew check` (tests plus Checkstyle, PMD, SpotBugs via the quality plugin)

Client (from `client/`, use Bun — `scripts/openapi-sync.sh` calls `bun`, even though `pnpm-lock.yaml` is also present):

- UI: `bun run dev` (Vite, default port 5173)
- Typecheck: `bun run check` (`svelte-kit sync` then `svelte-check`). There is no client test or lint script.
- `tsconfig.json` extends `.svelte-kit/tsconfig.json`, which does not exist until sync has run.

`JavaCompile` depends on `spotlessApply` and compiles with `-Werror`. A Gradle compile or test rewrites Java sources. Format is Eclipse rules in `server/src/quality/config/spotless/styling.xml`, not Google Java Format. Import order is project, then `java|jakarta|javax`, then `groovy`, `org`, `com`. Checkstyle also requires `final` locals, LF endings, no tabs, and a 140-character line limit.

## API wiring

Controller paths in `dev.ilionx.workshop.api.Paths` are `/v1/...`. The `/api` prefix is only `server.servlet.context-path`. New URLs go in `Paths`, not string literals on the mapping.

- Live calls: `http://localhost:8080/api/v1/...`
- MockMvc tests use an empty context path (`server/src/test/resources/application-test.yml`). Hit `Paths` constants, not `/api/v1`.
- OpenAPI JSON: `http://localhost:8080/api/v1/public/docs`. Swagger UI: `/api/v1/public/docs/openapi.html`. Health: `/api/v1/public/actuator/health`.
- `scripts/common.sh` waits on `/api/actuator/health`, which is not the configured actuator path. `bun run sync:api` can fail that wait even when the server is up. `download:api` assumes the server is already running and writes `server/openapi.json`.

Security permits every request. The client still sends Basic Auth (`user` / `password` in dev). Do not assume endpoints are locked down.

## DTOs and mappers

Do not return JPA entities or accept them as request bodies. Each feature keeps three shapes under `api/<feature>/model`:

- Entity on the table (`Owner`, `Pet`, …).
- `request/CreateXRequest` and `request/UpdateXRequest`. Lombok `@Data`, `@Accessors(chain = true)`, and `@Schema` on every field. Create and update are separate types even when the fields match.
- `response/XResponse`. Lombok `@Getter` `@Setter`, not `@Data`. Nested associations use a summary type (`PetSummaryResponse`), not the full child response.

MapStruct maps entity to response only. Mappers are abstract classes annotated `@Mapper(config = SharedMapperConfig.class)` in `model/mapper`, with `toResponse` and `toResponseList`. Flatten foreign keys with `@Mapping` (`owner.id` to `ownerId`). Do not add a MapStruct method for request to entity. Services copy request fields onto a new or loaded entity with setters, then `repository.save`.

Controllers call the service, then the mapper, and return `ResponseEntity` with an explicit status. They do not build response objects by hand.

## Liquibase

Migrations live in `server/src/main/resources/db/changelog/`. `db.changelog-master.yaml` `includeAll`s `db/changelog/changesets/`. Add a new XML changeset there; do not edit an already-applied changeset, and do not turn on Hibernate DDL (`ddl-auto` is unset, and `none` in tests).

- Changesets with no `context` always run (schema).
- Seed data is `context="tst"` only (`202507101201-TST-seed-data.xml`).
- `dev` and `test` set `liquibase.contexts=tst`. `dev` also sets `drop-first: true`, so in-memory H2 is wiped on every boot.
- Default profile in `application.yml` is `prd` and does not load seed data.

## Frontend API

The UI does not call `fetch`. `client/src/lib/api/client.ts` builds one `openapi-fetch` client typed as `createClient<paths>`, with `paths` imported from `$lib/types/api`. Base URL is `${VITE_SERVER_BASE_URL:-http://localhost:8080}/api`. Typed paths stay `/v1/...`. Do not add `/api` in `src/lib/api/*`.

- Do not hand-edit `client/src/lib/types/api.d.ts`. It is generated by `openapi-typescript`.
- Regenerate from a running server: `bun run download:api` then `bun run generate:api`, or `bun run sync:api` (that script starts the backend itself). Input is `server/openapi.json`. `client/src/lib/types/openapi.json` is not an input.
- `client/src/lib/api/models.ts` re-exports schema types under short names (`OwnerResponse`, `CreatePetRequest`). Import those, not `components['schemas']`, from pages and API modules.
- `src/lib/api/<feature>/<Feature>Controller.ts` is a thin wrapper: `client.GET` / `POST` / `PUT` / `DELETE`, `if (error) throw error`, return `data`. No business logic. Pages call these functions, not the client.

## Conventions

Package root is `dev.ilionx.workshop`. Features are `api/{owner,pet,vet,visit}` with `controller`, `service`, `repository`, and `model`.

- Names: `OwnerController`, `OwnerService`, `OwnerRepository`, `OwnerMapper`. Nested collections get a second controller: `PetController` is `/v1/owners/{ownerId}/pets`, `PetGlobalController` is `/v1/pets`. Same split for visits.
- IDs are `Integer`. Repositories extend `JpaRepository<Entity, Integer>` and add derived finders (`findByLastName`, `findByOwnerId`). Do not write `@Query` unless a derived name cannot express it.
- Services are `@Service` `@RequiredArgsConstructor` `@Transactional`. Reads are `@Transactional(readOnly = true)`. Methods are `findAll`, `findById`, `create`, `update`, `delete`.
- Missing rows throw `io.github.jframe.exception.core.DataNotFoundException` with an `ApiErrorCode` (`OWNER_NOT_FOUND`, and so on). Add a new code to that enum as the next `ERR-000N`. Do not throw `ResponseStatusException` or return a manual 404 body.
- Field validation is not Bean Validation on the entity. Owner create/update is the only flow that calls a `Validator` (`OwnerValidator.validateAndThrow`) in the controller, which throws `ValidationException`. Other features do not have that validator. `// BUG:` comments on entities are intentional workshop defects. Do not add the missing validation unless asked.
- Controllers carry `@Tag` and `@Operation`. Status comes from both `@ResponseStatus` and `ResponseEntity.status(...)`.
- Tests use Hamcrest `assertThat`, `@DisplayName("Should … when …")`, and method names `shouldXWhenY`. Given/When/Then comments are the local style. Service tests mock repositories with `mock(...)` and `BDDMockito.given`. Controller tests go through `mockMvc` and reuse `IntegrationTest` factories.

## Tests

Pick the base class by what the test touches. Both live in `server/src/test/java/dev/ilionx/workshop/support/`.

- `UnitTest` is `@ExtendWith(MockitoExtension.class)` and does not start Spring. Use it for `*ServiceTest` and other pure logic. It only supplies in-memory entity factories (`aValidOwner`, `aValidPet`, `aValidVisit`, `aValidVet`, `aValidSpecialty`). Mock collaborators in the test. Do not boot the context or hit a repository.
- `IntegrationTest` is a full `@SpringBootTest` (`test` profile, random port) with MockMvc and a real H2 database. Use it for `*ControllerTest`. It autowires every repository and supplies `aSavedOwner` / `aSavedPet` / `aSavedVisit` plus `aCreateXRequest` / `anUpdateXRequest`. Do not construct MockMvc yourself and do not `@MockBean` the service to dodge the database.

Each integration test deletes all visits, pets, and owners, then deletes only vets with `id > 6`, pet types with `id > 6`, and specialties with `id > 3`. Seed rows at or below those ids must remain. `aSavedPet` requires pet type id `1`. Do not expect seed owners or pets to still be present.
